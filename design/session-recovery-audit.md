# 取消、恢复与继续执行专项体检

本轮聚焦 turn-runner → session-commands → SessionManager，以及 index.ts 中工作树、提示词、任务/快照 scope 的接线。目标是验证中断后继续与会话切换的一致性。未修改原有 `.tmp/` 内容。

## 已复现并修复的问题

| 优先级 | 触发与原行为 | 修复与证据 |
| --- | --- | --- |
| P1 | 主目录与附加工作树有同 ID 会话，附加目录副本更新。列表展示新副本，定位/加载却优先主目录，继续任务时丢失最新上下文。 | 定位按 updatedAt 选择最新有效副本，同时间保留主目录优先。恢复集成测试验证消息、目录切换与续写位置，旧副本保持原样。 |
| P1 | 恢复其他工作树的损坏 JSON、缺失 messages、空会话。命令先切目录，加载失败仍留在目标目录；缺失 messages/空会话还可能替换当前 SessionManager 状态。 | 加载前校验有效消息与快照可复制性，加载成功后才调用工作树切换。四个失败用例检查当前会话、消息、目录、task/snapshot/agent scope 均不改变。只有 system 消息的文件也不接受为可恢复会话。 |
| P1 | 已有目标/加载技能的会话执行 `/clear`。元数据和技能状态清零，但直接复用旧 system prompt，新回合可能继续旧任务。 | 先清掉旧消息与压缩摘要，再按新会话状态重建提示词。行为测试断言下一轮使用重建后的 prompt。 |

最初新增的 6 个恢复行为测试在原实现上全部失败，修复后通过；随后补了损坏副本回退和归档边界两项测试。

## 新增回归覆盖

`packages/cli/test/session-recovery.test.mjs`：8 个用例。

- `/clear` 后重建提示词，不沿用旧目标、技能与压缩摘要。
- 列表、定位、加载使用最新有效副本，续写落在选中副本所在目录。
- 损坏的新副本不遮蔽有效旧副本，列表与加载采用相同有效性校验。
- 同时间归档不覆盖主副本；较新归档取回当前目录续写，归档保持原样。
- 损坏 JSON、缺 messages、空消息、只有 system 消息四种失败恢复保持当前状态。

`packages/cli/test/abort-tool-card.test.mjs`：新增 3 个行为用例。

- 请求发出前取消：prompt 不提交，回填输入草稿，可以重新发送。
- 正文生成中取消：保存部分回答，下一轮 Provider 能看到该内容并继续。
- 工具中止后立即继续：每条工具调用有且仅有一个配对结果，下一轮正常完成。

这三个取消场景在现有实现上通过，本轮没有修改取消执行逻辑。既有工具进程中止、授权卡取消、压缩与工作树测试也通过。

## 后续验证边界

本轮未验证外部进程在恢复过程中同时改写/删除工作树的竞争条件，也未做真实网络断开、强制杀进程和多终端并发压力测试；上述场景不据此宣称无缺陷。下一轮建议先补真实断网/重试与进程强退后的恢复场景，再测端到端耗时和人工介入次数。

## 补充：真实断网与强杀恢复（2026-10-28）

`packages/cli/test/failure-recovery.test.mjs` 现有 7 个用例，覆盖本轮建议的前两项：

- `socket-reset` / `early-eof`：真实本地 HTTP 连接在收到正文后被对端掐断，已产出的部分回复落盘、不自动重放请求，恢复后模型能看到这段内容。
- `HTTP 503`：首个请求 503 时按指数退避自动重试，用户输入只提交一次，最终回复落盘。
- **新增「对端不可达」**：先绑定再释放端口，确保 `127.0.0.1:<port>` 无人监听（真实 `ECONNREFUSED`，不是注入的假异常）。断言连接失败被判为可重试并进入第一次重试；在第一次重试时中止（等价用户看到断网后按 Esc），本轮不报完成、用户输入只落一条、不产生空 assistant 消息；随后在同一端口起真实服务，从磁盘恢复同一会话继续，模型只看到一条断网前的输入。
- 强杀进程三个边界（`second-tool` / `next-request` / `turn-finished`）：真实子进程 `SIGKILL`，恢复后已完成进度保留，缺回执的工具结果标为「状态未知」。

仍未覆盖：多终端并发写同一会话的压力测试、外部进程在恢复过程中同时改写/删除工作树的竞争条件，以及真实外网（DNS/中间设备）故障；这些不据此宣称无缺陷。
