# 网络故障与进程强退恢复体检

接续 `session-recovery-audit.md`。本轮使用真实本地 HTTP 连接、实际 Provider/流解析器/回合执行器/SessionManager，以及被父进程强杀的 Node 子进程验证恢复行为；终端、模型输出和工具执行使用测试替身，没有调用收费模型或改动实际网络设置。

## 发现与修复

| 问题 | 证据与修复 |
| --- | --- |
| 网络异常丢失已显示的部分回复 | 本地 HTTP 发送正文后销毁连接，恢复文件中没有 assistant 消息。现在错误路径与取消路径都保存正文和推理，不保存未完成的工具调用。 |
| HTTP 提前 EOF 被当成模型正常完成 | 服务端发送部分 SSE 后直接结束响应，原实现触发完成通知。现在缺少 `[DONE]` 且没有 `finish_reason` 时抛出中断错误，不交付工具调用。仍兼容任一单独结束标记及无尾换行的 `[DONE]`。 |
| 工具和回合边界存在延迟写盘窗口 | 子进程分别停在第二个串行工具开始、下一次模型请求开始、回合返回时强杀，原实现均丢刚完成的工具结果。现在 assistant 完成后（执行工具前）、每批工具结果处理后、回合结束返回前等待 flush。 |
| 不完整工具组恢复时丢弃已有成功结果 | 原 repairToolCallPairs 对缺结果的整组调用执行删除。新增可选 preserveIncomplete，仅恢复路径启用：保留合法调用及已有结果，给缺回执补“执行状态未知，先核实再重试”。默认压缩裁剪语义不变，非法调用仍移除。恢复修复在 UserPromptSubmit 压缩钩子之前执行，防止钩子先删掉结果。 |

初始 5 个故障注入用例在原实现全部失败（补齐测试终端 isInteractive 接口后确认），修复后全部通过。强退测试通过 IPC 通知边界，随后阻塞子进程事件循环再由父进程 SIGKILL，防止防抖定时器碰巧写盘掩盖问题。重新构造 SessionManager 加载文件并继续真实回合，验证已完成工具结果、会话目标和用量仍存在；没有自动重放历史工具。

## 保证与边界

- 这是执行边界检查点，不是逐 token 持久化。正在流式生成时直接强杀，尚未提交的正文/推理仍可能丢失；请求刚发出、首次防抖保存前也有窗口。
- 工具产生副作用到结果完成写盘之间仍有窗口。因此缺回执必须标为状态未知，不能声称工具没有执行，也不能提供 exactly-once 保证。并行批内尚未收齐的只读结果仍可能丢失。
- flush 使用现有原子替换和失败告警/待重试机制。磁盘不可写时不保证持久化成功；没有增加 fsync，不保证断电后磁盘缓存保留。未覆盖替换文件过程中强杀、磁盘满或系统崩溃。
- 本轮检查会话内消息、工具结果、目标和用量；独立 TaskStore、快照、子代理记录与会话之间的事务一致性未专项验证。
- 未覆盖多终端同时写同一会话、真实公网代理断连、真实模型服务、Windows Terminal 人工按键，以及全量 CLI 启动/退出钩子的故障注入。
- 增加了每个 assistant 完成点和工具批次后的等待写盘，长会话或慢磁盘上的耗时影响未做性能基准。

下一轮优先考虑持久化失败与退出清理的故障注入，随后验证 TaskStore / 会话 / 快照在强退时的一致性，以及多终端同会话写入冲突。
