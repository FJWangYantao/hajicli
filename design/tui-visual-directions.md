# haji TUI 视觉设计方向

> 独立视觉原型，不改变当前 TUI 的功能与交互。三版使用同一工作内容，对比布局、层级与密度，不只是换颜色。

## 打开原型

```bash
# 本地浏览器
xdg-open design/tui-visual-prototypes.html

# 渲染截图
pnpm shot design/tui-visual-prototypes.html
# 带参数时使用 file:// URL（将路径替换为你的仓库位置）
pnpm shot 'file:///home/ubuntu/hajicli/design/tui-visual-prototypes.html?scheme=paper'
pnpm shot 'file:///home/ubuntu/hajicli/design/tui-visual-prototypes.html?scheme=signal'
```

原型上方按钮或 `1 / 2 / 3` 切换方案；`N` 切换窄屏；`S` 切换侧栏。也可以用 `?scheme=editor|paper|signal&narrow=1` 直接访问。

## 现状判断

现有界面已有合理的信息骨架：顶栏承载会话与模型，对话区承载用户、回复与工具活动，侧栏按目标 → 任务 → 代理 → 上下文 → 费用排列，输入框和状态栏固定在底部。无需推翻。

主要视觉改进空间是：

1. **统一强调色**：工具路径、活动状态、选中项使用同一焦点色，不恢复工具区的一片青色。
2. **降低边框噪音**：用留白、缩进与细分隔线建立层级；输入框保留最明显的容器。
3. **主指标优先**：上下文优先读百分比/余量，费用优先读金额，其余默认折叠。
4. **状态不只靠颜色**：运行、完成、失败同时保留图形和文字；窄屏只收装饰，不丢关键数字。

## 01 静墨 / Quiet Editor —— 推荐默认方向

**低干扰深色 · 紫色焦点 · 中等密度**

- 保留现有深色与紫色品牌基因，但正文更亮、辅助文字更中性。
- 对话不层层套卡片，工具区只留左侧细线；侧栏用细分隔而非独立卡片。
- 上下文圆环改为细进度条，降低侧栏的视觉权重；所有关键数值保留。
- 输入框是最明确的可操作容器，焦点色只用于提示符、路径和当前状态。

适合：长时间编程、默认主题、希望“更精致但不改变习惯”的用户。

## 02 纸间 / Warm Paper

**暖白浅色 · 文档阅读 · 较大留白**

- 暖灰底与鼠尾草绿强调，不用纯白和饱和蓝，适合日间与阅读/审阅场景。
- 用户消息改为文档式引用，工具输出靠细分隔线组织。
- 侧栏是一块低对比纸面，正文保持近黑，不能以“更轻盈”为由使用浅灰正文。
- 段落与输入区增加呼吸感，适合作为浅色外观，不建议与深色混用局部颜色。

适合：写作、方案审阅、浅色终端用户；不能仅靠换色实现，需同时调整间距。

## 03 信号 / Dense Signal

**深色监控 · 琥珀焦点 · 紧凑密度**

- 保留深色，但焦点色从紫换为低饱和琥珀；工具状态仍使用绿/红语义色。
- 更紧凑的行距、分隔线、指标对齐，适合并行任务和大量工具记录。
- 默认收起长工具输出；不要用亮色铺满面板，运行态只用一个焦点色。
- 密度更高，但侧栏优先级、活动行只在对话区出现的原则不变。

适合：多任务监控、高频工具操作、希望一屏看到更多状态的用户。

## 推荐落地组合

默认深色选 **静墨**，浅色外观采用 **纸间** 的间距与层级原则；将 **信号** 作为可选紧凑密度，而非第三套全量主题。这样不需要维护三套完整 UI，且视觉差异覆盖真实使用偏好。

落地顺序建议：

1. `theme.ts`：先统一前景/弱化色/焦点色，保留深浅外观和 ANSI 256 色量化。
2. `terminal-input.ts` / `terminal-panels.ts`：输入区与工具块降噪，不动命中区域及折叠状态。
3. `tui-sidebar.ts`：视觉密度调整；必须保留目标 → 任务 → 代理 → 上下文 → 费用的顺序与三档高度降级。
4. 使用 `scripts/sidebar-gallery.mjs` 及主题、对比度、终端布局测试核对；原型中的 CSS 阴影、圆角等仅为视觉稿，不要求在 ANSI 终端中复刻。

## 原型验收口径

- 三版不是单纯配色变化：密度、留白、容器和侧栏处理均可区分。
- 对话区为视觉主角；工具路径与活动状态不使用青色。
- 侧栏关键指标与现有信息顺序保持；窄屏隐藏侧栏时对话可读。
- 深色正文、浅色正文均保持高对比；正文不要靠降低透明度建立层级。
