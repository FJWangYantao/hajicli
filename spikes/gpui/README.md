# GPUI Spike:画布压测 + 中文 IME

Route B(全原生 GPUI)的 go/no-go 验证项目。两个独立 bin,对应之前定下的两道门:

| Crate | 验证内容 | 运行 |
|---|---|---|
| `canvas-spike` | 气泡拖拽/缩放/平移 + 持续 FPS | `cargo run --release -p canvas-spike -- 100` |
| `ime-input-spike` | Input 组件中文输入法全流程 | `cargo run --release -p ime-input-spike` |

依赖锚点:`gpui-pre = 0.3.7`(= zed 主线快照 zed@1a28cff,2026-09-28 发布)+ `gpui-component = 0.7.0`(GPUI Kit 组件库,内部钉同一版本)。

## 为什么是这两个测试

1. **IME 是第一关**。自绘文本栈的中文输入(候选窗定位、组合中文本、Enter/空格语义)是 GPU 框架公认最难的坑,对中文用户产品是一票否决项。性能再好,输入有毛病就是零分。
2. **画布是第二关**。目标形态(可拖拽气泡画布)没有现成引擎,坐标变换/命中检测/框选都要自建——先把"GPUI 扛不扛得住满负荷重绘"测出来,再决定要不要投入自建。

## 测试清单

### canvas-spike(先 `cargo run --release -p canvas-spike -- 100`)

> FPS 数字必须看 release 构建;debug 构建只用来确认功能,数字无意义。

- [ ] 窗口打开,120 个带阴影彩色气泡 + 中文标签正常渲染(无豆腐块□)
- [ ] 左上角 FPS 计稳定在 **显示器刷新率**(60Hz 屏≈60,120Hz 屏≈120)——这是满负荷持续帧率,不是空闲帧率
- [ ] 拖拽单个气泡:跟手、无跳变、无残影;拖拽期间 FPS 不掉
- [ ] 空白处按住左键拖动 = 平移画布
- [ ] Ctrl+滚轮缩放,缩放锚点在光标处;普通滚轮平移
- [ ] 依次把数量拉到 1000、5000、10000(`cargo run --release -p canvas-spike -- 10000`),记录每个档位稳定拖拽时的 FPS
- [ ] 在任务管理器记录 100 / 1000 / 10000 档位的内存占用与 GPU 占用

**通过线**:1000 气泡拖拽 ≥ 60fps 且无肉眼卡顿;10000 气泡允许掉帧但不得崩溃/爆内存(>2GB)。

### ime-input-spike

用**微软拼音**逐项检查:

- [ ] 输入 `nihao` → 组合中文本 `nihao` 正常显示,光标位置正确
- [ ] 候选词窗口出现在输入框光标附近,**不是**屏幕左下角/不出现
- [ ] 空格选首选词上屏;数字键选指定候选;Esc 取消组合
- [ ] Enter 行为:上屏拼音原文(而非误触发其他快捷键)
- [ ] 组合中用方向键翻页选词正常
- [ ] 组合中点击窗口外(失焦)再回来,组合状态不残留错乱
- [ ] 输入长句(20+ 字)组合中整段显示不跳动
- [ ] Backspace 删除组合中字符正常
- [ ] 中英混排、粘贴中文正常

**通过线**:全部打勾 = 过;候选窗位置错误、组合文本丢失、Enter 语义错误三者任一出现 = 直接 no-go(除非确认能在自己代码里修)。

## 记录模板

```
机器:CPU / 内存 / 显卡 / 显示器刷新率 / Windows 版本
canvas:100→__fps  1000→__fps  5000→__fps  10000→__fps
内存:100→__MB  1000→__MB  10000→__MB
IME:候选窗位置[ok/异常] 组合文本[ok/异常] Enter[ok/异常] 翻页[ok/异常]
结论:go / no-go
```

## 结论之后的路

- **go** → 下一步不是直接做产品 UI,而是给画布加"框选 + 连线"(气泡 agent 形态的最后一块硬骨头),同时起 Iced(iced_nodegraph)对照组。
- **no-go(IME 不过)** → 退回 Figma 路线:Tauri + Rust/WASM 渲染核心 + DOM 文本输入层,性能与工程风险的最优折中。
